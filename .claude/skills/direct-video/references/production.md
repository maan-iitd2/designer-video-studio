# Production routes

Work inside the current film folder. Keep the approved words and beat timings in the brief. Choose the smallest route that can render the selected look and aspect. The two bundled starters are 16:9. A vertical film needs a portrait composition and a phone-size pilot to check framing and type.

| Route | First useful action |
|---|---|
| Paper collage | Copy `starters/paper-film-starter/` into the film folder. Show its `demo.mp4` if the designer wants a reference. Replace copy, cue times and image paths in `shots.json`. The bundled README covers dependencies. From the copied starter run `python make.py board`, then e.g. `python make.py clip --start 2 --end 5`, then `python make.py render`. Pick an interval that exists in the updated film. The optional `audio` field accepts a local mixed track. |
| Kinetic typography | Copy `starters/kinetic-type/` into the film folder. Replace the visible words in `compositions/main-graphics.html` and adjust the corresponding timeline cues. The sample runs silently over a colour field. It uses GSAP and web fonts. From that copy, preview with `npx --yes hyperframes@0.9.84 preview`. Pilot with `npx --yes hyperframes@0.9.84 render --start 0 --end 4 --fps 24 --quality draft --output pilot-v1.mp4`. For the full film omit the time range, set delivery quality, and use a new output name. On Windows, if the downloaded browser fails to launch, set `HYPERFRAMES_BROWSER_PATH` to the existing Chrome or Edge executable for the render. [Original kinetic sequence](https://github.com/heygen-com/hyperframes/tree/8c31cb3f400b20710ff76fda53354d7abfd6faca/registry/examples/kinetic-type) |
| Product demo or screenshot sequence | Pick one named [Video Shotcraft recipe](https://vincentwei1021.github.io/video-shotcraft/) and reuse the [Remotion template](https://github.com/Vincentwei1021/video-shotcraft/tree/main/template). Inspect just the selected recipe and its dependencies. Replace demo screens with hers. Preview the composition in Studio and render the selected composition to MP4. For a working Remotion project, extend that project directly. Check the applicable Remotion license for the producer. [Shotcraft](https://github.com/Vincentwei1021/video-shotcraft) · [Remotion](https://github.com/remotion-dev/remotion) |
| Talking head, interview or recorded tutorial | Use the transcript and selected intervals as the edit list. In a project-local [Herk Edit Kit](https://github.com/nateherkai/herk-edit-kit), start with its setup and `edit-video` or `cut-mistakes` skill. Preserve take decisions and caption the edited audio. Use its cards only where an overlay explains something. |
| HTML motion, diagram, annotation, custom explainer | Create a [HyperFrames project](https://github.com/heygen-com/hyperframes) inside the film folder with `npx hyperframes init my-video`, then preview and render there. One existing [Vox annotation component](https://github.com/heygen-com/hyperframes/tree/main/registry/components/vox-annotate) can time a highlight and callout to a spoken word. Use the actual data for charts. |
| Designer wants to edit on a timeline | Use [OpenFilm](https://github.com/openfilm/openfilm). In the working folder start with `npx -y openfilm@latest`. Its [entry skill](https://github.com/openfilm/openfilm/blob/main/skills/openfilm/SKILL.md) points to the film, media and canvas tools. Read the relevant one and open the project in its editor. Save the editable project alongside its export. |
| Documentary montage, stock search, characters or generated inserts | Use only the relevant [OpenMontage production pipeline](https://github.com/OpenMontageInc/OpenMontage) or [stock sourcing guide](https://github.com/OpenMontageInc/OpenMontage/blob/main/skills/creative/stock-sourcing-usage.md). Local photos and footage can be cut in the chosen renderer. For external media generation, verify provider access, per-second or per-image price, variations and retry allowance. Show the shot cost and a still/stock alternative before committing to the provider. |

For an unavailable tool, check its current official setup once, or use a simpler route compatible with the agreed look. Make a minimal technical export before building a long sequence. Keep screenshots, previews and logs small. A short error excerpt usually suffices.

## Local shot library

Run `python library/find.py "map route"` from the studio root, or pass a copied shot ID to get its paths. The gallery lives at library/index.html. Adapt assets in a copy in the current film folder.

- **Herk.** Copy the selected HTML and its style folder's tokens.css, preserving relative paths. Change the data-slot contents, colours and brand material. Use the existing GSAP timeline in HyperFrames.
- **Shotcraft.** Start from the local video-shotcraft/template project. Open the selected recipe and demo component. Keep its fixture, texture and asset imports when transplanting it. Use the matching MP4 as a timing reference.
- **HyperFrames.** The local registry-item.json declares the files, variables and destination paths for each piece. Copy the declared files into a working HyperFrames project and mount the composition using its demo.html or example index.html. Carry assets and any declared registry dependencies. The publisher page can show the interactive preview.
- **Preview assets.** Cards and demo footage illustrate the treatment. Replace the example copy, brands and media with material cleared for the new film. Each upstream collection retains its license and attribution.

## Metering and export

In Claude Code, `/usage` can show session and plan usage. Mark subscription usage as included and track paid extras separately. When using API billing in print mode, `claude -p --max-budget-usd <amount> "<bounded task>"` can limit that specific call. If the designer sets a limit, size the call to fit her remaining budget. Record the result. External providers and subsequent calls have separate meters. A plan user can stay with their subscription. [Usage](https://code.claude.com/docs/en/costs) · [CLI flags](https://code.claude.com/docs/en/cli-reference)

Use the renderer's own diagnostics and check the actual final file. For example, `ffprobe -v error -show_entries stream=codec_type,width,height:format=duration -of json final.mp4` reports its streams and timing. For a decode check, run `ffmpeg -v error -xerror -i final.mp4 -f null -`. Inspect the pilot and at least an opening, representative middle and closing frame. Keep the source settings, approved assets and rerender command with the project.
